## 2. 环境信息与账号

### 2.1 访问地址

- 学生/教师端：`http://47.93.4.199/`
- 健康检查：`http://47.93.4.199/api/health`（应返回 `{"status":"ok",...}`）

### 2.2 账号说明

| 角色 | 说明 |
|---|---|
| 超级管理员 | 全部权限，含用户/角色/部门管理 |
| 知识库管理员 | 文档、分类、视频、审核、补采、工单、敏感词、日志 |
| 院系管理员 | 按部门范围管理 |
| 老师 | 问答、文档、视频、我的学生 |
| 学生 | 问答、文档、视频、补采、工单、个人中心 |
| 访客 | 仅基础浏览与问答 |

- 管理员初始账号与密码由部署人员单独交接；**首次登录后必须立即修改密码**
- 学生账号由 `students.json` 批量导入，默认密码 `123456`，首次登录必须修改
- 登录需输入算式验证码；连续输错会触发账号临时锁定

### 2.3 运行模式（重要）

本系统支持两种运行模式，**默认且生产推荐云端 API 模式**：

| 模式 | 对话/向量 | 适用场景 | 状态 |
|---|---|---|---|
| 云端模式（默认） | 百炼 qwen-plus + text-embedding-v2 | 学校正式使用、多人并发 | 线上当前模式 |
| 本地离线模式（可选） | Ollama Qwen2.5-7B + BGE-base-zh（768 维） | 无外网演示、私有化展示 | 已实现并验证，需 GPU 工作站 |

- 本地模式存在速度（8～15 秒/问）、并发（单卡单请求）、检索覆盖和 7B 模型准确率等局限，且需要 GPU ≥6GB，**当前 2C3G 云服务器无法运行**
- 两种模式通过 `backend/.env` 切换；切换向量模型必须重建索引
- 完整对比、局限说明与部署步骤见《部署模式与本地大模型说明》（`docs/部署模式与本地大模型说明.md`）
- 验收时需确认：实际运行模式与 `.env`、验收记录三者一致

## 3. 验收前置检查

在服务器执行（需 SSH 权限）：

```bash
systemctl is-active kb                 # 期望：active
curl -s http://127.0.0.1:8001/api/health   # 期望：{"status":"ok",...}
nginx -t                               # 期望：syntax is ok
```

数据完整性（后端目录下执行）：

```bash
cd /opt/kb/backend
python - <<'PY'
import sqlite3
c = sqlite3.connect("data/enterprise_rag.db")
print("documents:", c.execute("select count(*) from documents").fetchone()[0])
print("chunks:", c.execute("select count(*) from doc_chunks").fetchone()[0])
PY
```

期望：文档数、分块数均大于 0；若为 0 说明数据未导入，禁止验收。

## 8. 已知限制（须向验收方说明）

1. **默认云端模式**：正式使用请保持云端 API；本地离线模式为可选方案，速度、并发与检索覆盖均弱于云端（详见《部署模式与本地大模型说明》）
2. **检索覆盖不完整**：I2C 与 SPI 对比、树莓派 GPIO 等知识点语料较少，回答可能依赖模型通用知识，须回看来源核实
3. **7B 本地模型**：示例代码/API 签名可能出错，不能作为唯一依据
4. **并发能力**：本地模式单卡单请求，多人同时提问会排队
5. **传输安全**：当前部署为 HTTP，如需公网正式使用应先配置 HTTPS
6. **备份**：当前未配置自动备份，需按附录 B 建立定时任务
7. **爬虫子系统**：采集/标注依赖外部模型 API，断网时不可用；问答链路可离线

## 附录 B：备份与恢复（建议每次验收前执行一次）

```bash
# 备份
mkdir -p /opt/backup
cd /opt/kb
tar czf /opt/backup/kb_$(date +%F).tar.gz \
    backend/data/enterprise_rag.db \
    backend/chroma_data/faiss_index \
    backend/bm25_index.pkl \
    backend/uploads

# 恢复（停服后）
systemctl stop kb
tar xzf /opt/backup/kb_YYYY-MM-DD.tar.gz -C /opt/kb
systemctl start kb
curl -s http://127.0.0.1:8001/api/health
```

> 索引与主库必须成对恢复，单独恢复其一会导致检索为空或结果错乱。

## 附录 C：常见故障处理

| 现象 | 处理 |
|---|---|
| 页面 502 / 白屏 | `systemctl status kb`；`journalctl -u kb -n 80`；确认 8001 端口监听 |
| 问答检索为空 | 检查 FAISS/BM25 文件是否存在；必要时重建索引 |
| 页面还是旧版 | 浏览器 Ctrl+F5；确认 `index.html` 无强缓存 |
| 学生无法登录 | 确认已执行 `sync_students.py`；默认密码 123456；是否被锁定 |
| 验证码不显示 | 检查 `.env` 的 `CAPTCHA_ENABLED` 与后端日志 |
